RECORDAR - BACKEND (Proyecto-Investigacion_Backend)
====================================================

ORDEN PARA ECHAR A ANDAR LA PAGINA EN LOCAL
  1. Encender MySQL.
  2. Encender el backend (esta carpeta).
  3. Encender el frontend (carpeta Proyecto-Investigacion_Frontend).


CADA VEZ QUE QUIERA USARLO
--------------------------
  1. Verificar que MySQL este encendido.
  2. Abrir una terminal en esta carpeta y ejecutar:

         npm run dev

  3. Debe aparecer:

         Conectado a la base de datos "bdinvestigacion".
         API escuchando en http://localhost:3000

  4. Dejar esa terminal abierta. Se apaga con Ctrl + C.

  Prueba rapida en el navegador:
         http://localhost:3000/api/proyectos     (debe mostrar los proyectos en JSON)


SOLO LA PRIMERA VEZ (o en una computadora nueva)
------------------------------------------------
  1. npm install
  2. Importar en MySQL, en este orden, los archivos de la carpeta database:
         00_crear_bd.sql
         01_proyecto.sql
         02_usuario.sql
         03_icono_proyecto.sql
  3. Copiar .env.example como .env y llenar:
         DB_USER       usuario de MySQL
         DB_PASSWORD   contrasena de MySQL
         JWT_SECRET    un texto largo y aleatorio
  4. Crear el primer administrador (ver reglas en ADMINISTRADORES):
         npm run crear-admin -- <correo institucional> <contrasena>


ADMINISTRADORES
---------------
  - Lo normal es darlos de alta desde la pagina: Panel > Administradores.
  - El usuario de una cuenta nueva SIEMPRE es un correo institucional:
         nombre@itslerdo.edu.mx
    (el dominio se puede cambiar con DOMINIO_CORREO en .env)
  - La contrasena debe tener, a fuerza: minimo 8 caracteres, una mayuscula,
    una minuscula, un numero y un simbolo (por ejemplo # $ % & ! ?).
  - Desde la terminal (para el primer administrador, o si olvide mi contrasena):
         npm run crear-admin -- <correo institucional> <contrasena>
    Si la cuenta ya existe, ese comando solo le cambia la contrasena.
    Poner la contrasena entre comillas simples para que PowerShell no altere los simbolos:
         npm run crear-admin -- Admin 'password1234'
  - La cuenta inicial "Admin" se conserva aunque no sea un correo.
  - Nadie puede eliminar su propia cuenta; asi nunca se queda el sistema sin administradores.
  - Al eliminar una cuenta, su sesion deja de servir de inmediato.
  - Evitar la letra enie y acentos en la contrasena si se escribe desde PowerShell.
  - La contrasena se guarda cifrada: no se puede crear ni cambiar a mano en phpMyAdmin.
  - La sesion dura 8 horas (JWT_EXPIRA en .env).


DETALLES IMPORTANTES
--------------------
  - El archivo .env tiene las contrasenas. NO se sube a GitHub (ya esta en .gitignore).
  - Puerto de la API: 3000 (PORT en .env).
  - El backend solo acepta peticiones del frontend en http://localhost:5173
    (CORS_ORIGIN en .env). Si el frontend abre en otro puerto, cambiar ese valor
    y reiniciar el backend.
  - Si cambio algo en .env hay que reiniciar: Ctrl + C y otra vez npm run dev.
  - Base de datos: bdinvestigacion. Tablas: proyecto y usuario.
  - La tabla proyecto tiene la columna ICONO (agregada con 03_icono_proyecto.sql).
    Si ya tenia la base funcionando, solo importar ese archivo una vez.
  - Despues de actualizar el codigo del backend hay que reiniciarlo.


PROBAR LA PAGINA DESDE EL CELULAR (misma red que la PC)
-------------------------------------------------------
  Desde el celular "localhost" es el propio celular, por eso hay que usar la IP de la PC
  y cambiar 3 cosas. Se hace solo para probar; al terminar se deja todo como estaba.

  1. Conectar el celular a la misma red que la PC (zona Wi-Fi de Windows o el mismo Wi-Fi).
  2. Ver la IP de la PC: en PowerShell ejecutar  ipconfig  y copiar la "Direccion IPv4"
     (ejemplo usado en las pruebas: 192.168.1.6; con la zona Wi-Fi de Windows suele ser
     192.168.137.1). La IP puede cambiar al reconectarse: si deja de funcionar, repetir este paso.
  3. Cambiar los dos .env (cuidar que la IP este bien escrita, ese fue el error de las pruebas):
         Backend  (Proyecto-Investigacion_Backend\.env):
             CORS_ORIGIN=http://<IP DE LA PC>:5173
         Frontend (Proyecto-Investigacion_Frontend\.env):
             VITE_BACKEND_URL=http://<IP DE LA PC>:3000/api
  4. Reiniciar los dos (Ctrl + C y de nuevo). El .env solo se lee al arrancar, y el backend
     NO lo recarga solo aunque use node --watch.
         Backend:   npm run dev
         Frontend:  npm run dev -- --host
  5. Abrir en el celular (y tambien en la PC) http://<IP DE LA PC>:5173
     OJO: el backend solo acepta UNA direccion en CORS_ORIGIN. Con la IP puesta, abrir la
     pagina como localhost:5173 en la PC deja de cargar los datos; usar tambien la IP.
  6. Si la pagina abre pero no muestra proyectos, probar en el navegador del celular
     http://<IP DE LA PC>:3000/api/proyectos
         - Si no carga: Firewall de Windows. Abrir PowerShell como administrador:
             New-NetFirewallRule -DisplayName "Dev portal API" -Direction Inbound -Protocol TCP -LocalPort 3000,5173 -Action Allow -Profile Any
           y al terminar de probar quitarla:
             Remove-NetFirewallRule -DisplayName "Dev portal API"
         - Si carga el JSON: revisar F12 > Consola; "blocked by CORS" = CORS_ORIGIN no coincide
           exactamente con la direccion escrita en el navegador.
  7. AL TERMINAR devolver los .env a localhost y reiniciar los dos:
             CORS_ORIGIN=http://localhost:5173
             VITE_BACKEND_URL=http://localhost:3000/api
         y volver a usar  npm run dev  a secas en el frontend.


SI ALGO FALLA
-------------
  "Faltan variables en el archivo .env"
        No existe .env o falta DB_USER, DB_NAME o JWT_SECRET.
  "No se pudo conectar a la base de datos"
        MySQL esta apagado, o el usuario/contrasena de .env no coinciden.
  "Table 'bdinvestigacion.usuario' doesn't exist"
        Falta importar database/02_usuario.sql.
  "Unknown column 'ICONO'"
        Falta importar database/03_icono_proyecto.sql.
  "EADDRINUSE ... 3000"
        Ya hay otra terminal con el backend encendido. Cerrarla o usar esa.
  El login rechaza una contrasena correcta desde PowerShell
        Pasa con enie o acentos. Desde la pagina funciona; mejor usar una
        contrasena sin esos caracteres.
